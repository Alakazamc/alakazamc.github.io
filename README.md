# 柯西 Alakazam · 个人站

静态站点源码与已生成页面保存在同一仓库。文章在 `content/posts/`，构建脚本在 `build/`；日常写作入口为 [写作台](https://alakazamc.github.io/write/index.html)。

## 写作与草稿保护

- 打开其他文章或本机草稿前，未保存的修改会触发「保存草稿并打开 / 放弃修改并打开 / 取消」选择；取消、读取失败或保存失败不会替换当前文章。
- 草稿只保存在当前浏览器，按文章分别保存；无标题的新文章也能保存。用「打开本机草稿」找回其他草稿。旧版单草稿仍可恢复，不会在迁移时删除。
- 正文、标题、日期、标签、摘要、文件名和封面都参与修改检查。刷新或离开页面时浏览器会提示未保存的修改，但移动端或强制关闭不保证触发提示，请及时保存草稿。
- 载入过程中继续输入、取消载入或改选其他文章，不会被慢返回的旧请求覆盖。打开文章会载入其封面；没有封面则清空。
- 草稿不会上传或发布。清理浏览器数据、换设备或使用无痕窗口可能导致草稿不可恢复；重要内容应另留备份。

## 本地检查

使用 Node.js 22 或更高版本，无需安装依赖：

```sh
node --test tests/*.test.js
node build/gen.js
```

测试执行写作台的实际内联脚本，覆盖取消、保存失败、分别恢复草稿、旧草稿兼容、连续选文、慢请求、输入期间载入、封面恢复及离页保护。它们不代替实体手机或真实 GitHub 发布验收。`tests/github-contributions.test.js` 覆盖贡献派生与翻页分页：年度总数、连续活跃天数（今天为空不算断）、残周补齐、`pageWindow()` 的分页/越界夹回/区间日期、旧快照降级，以及快照里不许出现仓库名。

构建会更新 `write/index.html` 等生成页面。修改写作台请编辑 `build/blog-editor.html`，不要只改生成副本。

## 贡献热力图

首页「工坊」面板显示贡献热力图：可前后翻页的四周一屏，带月份分隔、星期列头和悬浮气泡；上方三个数字是近一年总贡献、连续活跃天数、最近活跃日期。

- 数据来自 GitHub GraphQL 的 `contributionsCollection`，查询与派生都在 `build/refresh-github.js`，快照落在 `build/data/github.json`。
- 口径是**贡献**（commit + PR + issue + review）而不是「提交」：含私有的数字 GitHub 只给聚合贡献数，commit 明细一律只统计公开仓库，写「提交」会和 GitHub 个人页对不上。
- 总数**包含私有与组织仓库**的贡献，与 github.com/Alakazamc 个人页显示的是同一份数据；私有仓库名一律不进入快照（`build/data/github.json` 是公开可读的）。
- 一屏只画四周（`build/refresh-github.js` 的 `PER_PAGE`）：全年 53 周里非空格子不足一成，一次性画出来是一整片灰。整年数据都在快照里，面板上的 ‹ › 可以一路翻回一年前。
- 翻页的起止区间由 `pageWindow()` 算（纯函数，有单测），客户端只做「窗口起始日 + 序号」一件小事 —— 区间和气泡里的日期**带两位年份**，翻到去年才不会看错。
- 五档深浅的透明度下限不是随手定的：每一档跟面板底的对比度都要过 3:1（WCAG 1.4.11，承载信息的图形必须能分辨）。浅档从 0.34 提到 0.7 就是为这个，本地探针每次都会量这道线。
- 数字在构建时烘焙进页面，由「重建站点」工作流每天北京时间 06:23 刷新一次，不是实时的。
- 快照缺失或字段不全时整块不渲染，不影响构建 —— PR 检查会拿仓库里现有的旧快照跑 `node build/gen.js`。

## 发布

沿用现有流程：修改经 PR 检查后合并到 `main`；`content/**` 或 `build/**` 的更新触发「重建站点」，自动提交生成页面，再由 GitHub Pages 发布。构建工作流的路径过滤用于防止生成提交反复触发重建，请保留。本站没有版本标签或 GitHub Release 流程。
